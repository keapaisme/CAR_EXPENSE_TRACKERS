# 🤖 愛車支出記錄專案：AI 開發行為約束規則 (AGENTS.md)

本專案已完全重構為純前端 HTML+GAS 直連的車主專屬支出記錄系統。所有後續接棒的 AI 助理必須嚴格遵守以下開發、備份與專案日誌管理規則：

---

## 1. 📂 專案日誌管理模式 (同日本旅遊2026)
每次對專案程式碼（特別是 `index.html`）進行任何功能修改、Bug 修復或排版重構時，AI **必須在結束該輪對話前**執行以下文件維護：
1. **建立專案日誌**：在 `日誌/` 目錄下建立一個 markdown 檔案，命名格式為 `YYYYMMDD_序號.md`（例如：`20260707_01.md`），詳述基本資訊（依據檔案、Token 消耗與粗估費用）、核心異動說明以及本期新增/解凍項目。
2. **同步文件清單**：檢查並更新根目錄下的 [文件清單.md](file:///Users/kas/Documents/PythonProject/Expense_tracker/文件清單.md)，載入最新檔案異動、修改日期與關聯之日誌編號。
3. **同步決策凍結記錄**：將新確立的開發架構、隱私原則或 UI 設計規範，以時間軸形式追加登錄於 [凍結記錄.md](file:///Users/kas/Documents/PythonProject/Expense_tracker/凍結記錄.md) 中，以防止往後開發產生資訊漂移。

---

## 2. 📦 程式碼版本化與備份機制 (v1.0)
- **版本編號與簡述**：所有修改後的程式碼/網頁，必須在檔案最頂端以註解標記版本編號（如 v3.1），並附上 **100 字以內**的簡要說明。
- **備份目錄**：前一代的舊版本檔案一律搬移至專案目錄底下的 `bak/` 資料夾中。
- **副檔名與輪替**：備份檔案之副檔名依序命為 `index.html.bak01`、`index.html.bak02`、`index.html.bak03`。
- **版本上限**：每個檔案至多保留 **3 個備份版本**。當有新版本產生時，舊備份依次向後輪替（原檔 ➔ `.bak01` ➔ `.bak02` ➔ `.bak03`），最舊的第四代版本則予以刪除。

---

## 3. 🔒 隱私與資安防禦原則
- **試算表 ID 保護**：**絕對不得**將 Google Sheets 試算表的 ID 暴露或寫死在前端 `index.html` 原始碼中，以防止被公開存取。
- **GAS Token 驗證**：網頁與 GAS Web App 端點之間的存取必須採用 Token 密鑰驗證。
- **設定優先權**：網頁頂部支援 `DEFAULT_GAS_API_URL` 預設連線變數。若 `localStorage` 無設定則自動讀取該常數，方便使用者部署即用。

---

## 4. 🧹 測試資產與臨時檔案管理規範
- **臨時目錄限制**：所有生成式媒體（如 TTS 音訊、試聽檔、AI 插圖、臨時腳本）在測試與調試階段，**一律強制產生於專案 `.tmp/` 或 agent 專屬 scratch 目錄中**，絕對禁止直接寫入專案根目錄。
- **自動清理機制**：當測試驗收通過並搬移正式檔案至 `assets/` 後，AI 必須在對話結束前主動執行清理，刪除 `.tmp/` 及所有臨時測試產物。
- **Git 防禦規則**：專案根目錄 `.gitignore` 必須包含 `.tmp/`、`test_*` 等規則，避免測試資產被提交或同步上雲端。
